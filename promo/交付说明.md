## 二、重新生成

```powershell
# 1. 配乐（游戏原声，裁切 + 电平）
node promo\tools\build_audio.mjs

# 2. 字幕
node promo\tools\make_subs.mjs

# 3. 逐帧渲染（88s ≈ 2640 帧；可加 --start/--end 分段并行）
node promo\render\shoot.mjs --start=0 --end=88 --video=promo/render/video.mp4 --preset=medium --crf=17

# 4. 合轨 + 烧字幕
ffmpeg -y -i promo/render/video.mp4 -i promo/audio/mix.wav `
  -vf "ass=promo/out/subs.ass:fontsdir=promo/fonts" `
  -af "volume=0dB" `
  -c:v libx264 -preset slow -crf 18 -pix_fmt yuv420p -c:a aac -b:a 192k `
  -movflags +faststart -shortest promo/out/spymouse-promo-1080p.mp4
```

改节奏只改 `promo/stage/timeline.json`（镜头区间 + 字幕起点），三处会一起生效。

> **镜头时长与字幕对齐**：`app.js` 不再做「按比例压缩时间」的缩放，每个镜头收到的
> 就是它真实的本地秒数；镜头内部的关键动作（越狱徽章、安卓卡片、模拟器无响应、
> 便签、点赞、分享、片尾）都按原稿断句的绝对时间写死，所以配音照着字幕念就能对上。
> 改镜头区间后，需要同步调整该镜头 `return (t) => {}` 里的时间常数。

> **转场**：`app.js` 顶部的 `TRANS` 表按「进入哪个镜头」登记转场：
> `dissolve`（叠化）/ `push`（横向推移）/ `wipe`（硬边横扫）。
> 镜头会多保留 `dur` 秒用于转场，因此切点两侧都是完整构图，不会出现空帧或闪白。

> 本次成片是 5 段并行渲染后拼接的（0–20.3 / 20.3–42.1 / 42.1–58.9 / 58.9–76.6 / 76.6–88），
> 拼接方式是 `concat` 滤镜后同一次编码，画面无二次压缩损失。
